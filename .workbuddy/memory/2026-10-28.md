## 后端字段对齐 + 首次真实联调（交易/支付链路）

**环境**：MySQL 8.0.46（STRICT_TRANS_TABLES）、Redis（密码 123）、RabbitMQ、ES、Nacos 均在 `124.220.155.27`。JDK17 在 `E:\develop\tools\jdk\javaversion\jdk-17`，Maven 在 `E:\develop\tools\maven\apache-maven-3.9.16`。注意沙箱注入了 `SERVER__PORT` 环境变量，会覆盖 `server.port`，起服务需 `--server.port=` 参数覆盖；curl 需 `--noproxy '*'`。

**修掉的 5 个真问题**
1. `tb_order.order_no` / `tb_order_detail.seller_id` / `tb_pay_order.payment_no` / `tb_pay_event_outbox.payment_no` 都是 NOT NULL 无默认值，而实体没有对应字段 → 严格模式下 INSERT 直接 1364。已补实体字段 + `BizNoGenerator` 生成业务号 + 幂等迁移脚本 `database/08_align_trade_payment.sql`（新增 payment_type/consign_time/spec/update_time 四列）。
2. 网关不剥 `Authorization: Bearer ` 前缀 → 所有需登录接口必然 401（前端一直按标准发 Bearer）。已在 `AuthGlobalFilter` 里剥离，并顺带堵住公开接口伪造 `user-info` 的洞。
3. `ItemServiceImpl.deductStock` 把枚举 `ItemStatus.SOLD` 直接写进 tinyint 列 → `Incorrect integer value: 'SOLD'`，下单必失败。改成 `getValue()`。
4. 5 个服务 `REDIS_PASSWORD` 默认空，而 Redis 实际密码是 123（只有活动服务配了）→ 支付/购物车等服务一用 Redis 就 NOAUTH。统一为 `${REDIS_PASSWORD:123}`。
5. 重复的 `payment/enums/PayStatus`（与 `domain/PayStatus` 语义冲突且无人引用）已删除；`07_payment.sql` 里与代码相反的 status 注释已改正。

**验证**：经网关跑通 注册→登录→下单→支付(mock)，`tb_order.status=2`、`tb_pay_order.payment_no` 有值、outbox `published=1`、`tb_item.status=3`，测试数据全部回滚。`mvn -DskipTests compile` 全量通过。
